# OpenBuildNet v0.1 單節點執行規格

單一節點接收本機提交的建構任務，在隔離環境執行，並讓提交者依任務 ID 取得狀態、日誌、退出碼與產物。同一份任務描述及結果格式可供後續雙節點派工沿用。

## 任務輸入

- 輸入來源為提交時固定的原始碼快照。
- 任務指定執行環境、依序執行的命令與參數、允許注入的環境變數、執行時限，以及工作區內要收集的相對路徑。
- 節點驗證輸入、執行環境及本機資源政策，接受後配置任務 ID 與本次執行 ID。重試時可沿用任務 ID 並配置新的執行 ID。

## 執行狀態與結果

| 狀態 | 條件 |
| --- | --- |
| queued | 已接受，等待隔離環境及執行容量 |
| running | 已啟動建構程序 |
| succeeded | 步驟均以零退出，指定產物已收集 |
| failed | 命令失敗、隔離環境啟動失敗，或指定產物收集失敗 |
| timed_out | 超過執行時限，節點已停止本次執行 |

結果包含兩種 ID、最終狀態、時間、日誌位置、退出碼（程序有回報時）及已收集產物清單。基礎設施錯誤另記原因。節點重啟後應能查詢已完成結果，並將確認中止的執行標為失敗。

## 隔離邊界

- 每次執行配置獨立工作區，從快照匯入建構輸入。預設隔離主機檔案、憑證與網路，並限制 CPU、記憶體、儲存量及時間。
- 執行環境無法套用必要限制時，回報失敗。產物收集限於指定工作區路徑，並驗證實際目標仍位於工作區內。
- 第一版以一種執行環境驗收。具體後端待實作前確認。

## 驗收

- 提交成功任務，可依 ID 讀到狀態、日誌、退出碼 0 與指定產物。
- 提交會回傳非零退出碼的任務，可查到失敗狀態、退出碼及日誌。
- 超時任務停止執行並保留日誌。隔離環境無法啟動時可查到失敗原因。
- 在隔離環境內驗證預設無法讀取主機測試檔或存取網路，並驗證產物收集會拒絕指向工作區外的路徑。
